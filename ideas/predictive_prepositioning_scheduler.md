# Idea — 예측 기반 Pre-Positioning 글로벌 스케줄러

> **노드-로컬 steering 을 제거하고, 스케줄링을 전부 CPU 글로벌 스케줄러로 위임한다.**
> 노드는 글로벌이 정해준 배치를 *실행만* 한다. 완료가 결정론적이므로 글로벌이 빠질 것을
> 미리 계산해 *정확한 길이의 요청을 pre-position* 한다. 여기에 **멀티턴 대응 on-node KV 캐시**와
> **글로벌 풀 age-cap** 을 더한다.

---

## 현재 → 신규

| | 현재 (로컬 steering) | 신규 (글로벌 pre-positioning) |
|---|---|---|
| 노드 배치 선택 | 노드가 매 라운드 잉여+완료분에서 steering 재선택 | **삭제** — 노드는 실행기 |
| 잉여(surplus 10) | 노드에 랜덤 잉여 상주 | **삭제** — 활성 2배치(124=2×62)만 상주 |
| 힐링 | 노드 per-completion `ideal=hole` | **삭제** — 글로벌이 결정론 presend |
| 완료 KV | 캐싱 없이 방출 | **on-node KV 캐시**(멀티턴 대응) |
| 공정성 | 노드 동작점 age-cap | **글로벌 풀 age-cap** 으로 이동 |

선택 로직이 사라지는 게 아니라 **글로벌로 올라가 결정론적이 된다.**

---

## 전제 — 멀티턴 = 오프로드

- 턴 사이 think-gap(≫ 응답시간) 동안 KV 를 HBM 에 두는 건 비싸다 → 오프로드.
- 멀티턴 복귀 = "캐시/디스크에서 **더 길어진 새 arrival**" 과 동치(누적 컨텍스트가 새 요청으로 재진입).
- 상태 전이는 셋뿐: **prefill→decode(노드 내)** · **종료→방출(+선택 캐시)** · **parked→오프로드**.

---

## 동작

1. **콜드 스타트 (초정밀 1회):** 글로벌이 124(=62+62)를 평균 100K 에 *정확히* 맞춘 2배치로 구성.
   용량 초과 long 은 **엣지 게이팅**으로 edge 노드行.
2. **정상 상태 — 결정론 pre-positioning:**
   - **완료는 결정론적이다.** 완료 = `max_tokens`(= 읽어야 할 KV 횟수 = 디코드 스텝 수) 도달.
     EOS(마지막 토큰 시점)는 완전 랜덤이라 *보지 않는다*. → decode 길이 = `max_tokens`, **jitter 0**.
   - 글로벌이 각 노드의 in/out 흐름(언제 무엇이 빠지고 남는지)을 결정론적으로 계산 →
     빠질 슬롯을 채울 **정확한 길이**의 요청을 글로벌 풀에서 골라 *미리* presend.
   - 두 활성 배치가 *항상* 평균 100K 에 정확히 센터 → 랜덤-잉여 cherry-pick 오차 제거.
   - **디코드 측엔 슬랙이 불필요**(완전 결정론). 유일한 stochastic = **멀티턴 복귀 *도착 타이밍***.
3. **노드 = 실행기:** 노드는 결정론 배정 배치를 실행만 한다.

## on-node KV 캐시 (멀티턴 대응)

- **무엇을:** 디코드 완료 시 길이가 **적격 임계(스윕)** 를 넘는 mid·long 요청의 KV. (짧은 건 하위계층
  재로드가 싸서 캐싱 가치↓. 길수록 ① 복귀확률↑ ② 재계산·재로드 비용↑ → 캐싱 가치↑.)
- **용량:** derive 산출 잔여 = `hbm_capacity_tb − instance_a_tb`(가중치 + 활성 2배치 제외, 70B≈**1.33TB**).
  **하드코딩 금지** — 모델·HW·die-stack 별 산출. *고정량이지 스윕 knob 아님.*
- **admission:** 별도 개수/용량 캡 없음 — **잔여 용량 ≥ KV 크기면 무조건 들어간다.** 그래서 잔여가
  차면 자동으로 막히고, **영원 점유를 막는 유일한 장치가 evict-age** 라 그게 결정적.
- **방출:** **evict-age(스윕)** = wall-clock idle 임계. 마지막 턴 후 오래 idle = 복귀 안 함 → 방출.
- **메모리 계층 3단:** HBM(=hit) → SSD 등 하위(=miss·재로드) → 완전 소멸(=miss·재계산).

### 캐시 히트 비용 모델 (causal attention)

디코더 LLM 어텐션은 **인과적(causal, 한방향)** 이다 — P1 토큰은 미래의 P2 를 참조하지 않으므로
**P1 의 KV 는 턴1에서 계산된 그대로 최종값**이고, 그래서 캐싱이 정당하다. 복귀 시 P2 는 **캐시된
P1 의 KV 를 읽어** 참조한다(맥락 보존) — P1 을 다시 만들지 않는다. 즉 hit = "긴 과거는 공짜,
짧은 새 턴 P2 만 프리필".

캐시된 KV = `[P1 = 이전 프롬프트 + 이전 생성 디코드 토큰]`. 복귀 컨텍스트 = `[P1 + P2(새 메시지)]`.

| 경우 | 재로드 | P1(과거) 재계산 | P2(새 메시지) 프리필 |
|---|---|---|---|
| **Hit** (HBM 상주) | **0** | **0** (캐시 KV 참조) | 지불 |
| Miss · SSD 생존 (evict-age 후~소멸 전) | 속도⁻¹ × P1 바이트(∝길이) | 0 (로드로 복원) | 지불 |
| Miss · 완전 방출 | — | **전체 재계산** ∝ P1 | 지불 |

- 캐시가 아끼는 것 = **P1 의 재로드 + 재계산.** P1 이 길수록(쌓인 디코드 토큰 포함) 절약↑ → 긴 요청
  캐싱이 정당.
- 새 메시지 P2 프리필은 **어느 경우든 항상 지불**(진짜 새 토큰).
- reload 시간 = **상수 속도(offload BW, 가정 라벨) × KV 바이트**. 시간을 상수로 박지 말 것.

**가중치 통과 vs attention — 무엇을 건너뛰나.** 트랜스포머에서 위치를 섞는 건 attention 뿐이다
(QKV proj·O-proj·FFN 은 토큰별 독립). hit/생존이 건너뛰는 건 **P1 의 KV 재생성(가중치 통과)** 이고,
**attention(=묶는 행위)은 어느 경우든 `[P1+P2]` 전체에 대해 해줘야 한다**(P2 query 가 P1 KV 를 읽어야
맥락 보존).

| 경우 | 가중치 통과 (QKV proj · O-proj · FFN) | Attention (query × key/value) |
|---|---|---|
| **Hit** | **P2 토큰만** | **P2 query × `[P1 ⊕ P2]` KV** — P1 KV 는 HBM 캐시에서 읽음 |
| **Miss·SSD 생존** | **P2 토큰만** | **P2 query × `[P1 ⊕ P2]` KV** — P1 KV 는 SSD→HBM 재로드 후 읽음 |
| **Miss·완전 방출** | **P1 + P2 전부** | **`(P1+P2)` query × `(P1+P2)` KV** (causal) — 전부 재생성 |

핵심 비대칭: **key/value 축은 세 경우 모두 `[P1+P2]` 전체**(P2 가 과거를 봐야 하므로 binding 은 안 빠짐);
차이는 **query** — hit/생존은 새로 계산하는 query 가 **P2 만**, 완전 방출만 P1 의 KV·출력을 레이어마다
다시 만들어야 해서 **query = P1+P2 전부**.

## 글로벌 풀 age-cap (라우팅 FIFO 공정성)

현 글로벌 라우팅은 **길이-fit 만 보고 도착 순서를 안 본다** → 어정쩡한 길이가 글로벌 풀에서 영원히
패스당할 수 있다. 노드 동작점 age-cap 은 *노드에 이미 들어온* 풀만 봤고(본 설계에서 사라짐),
**글로벌 풀 starvation 은 아무도 안 막는다.**

→ **글로벌 풀에도 age-cap(스윕).** 풀 대기가 cap 을 넘으면 **필요한 길이에 가장 가까운 노드로 강제
배정.** off-fit 은 글로벌 composer 가 같은 배치 나머지를 보정해 흡수(평균 100K 유지) — 노드 steering
자기보정의 글로벌 판. ⚠ **시뮬에서 강제 진입 개수를 카운트**(공정성↔정밀도 트레이드오프 측정).

- **본 설계의 주(主) 공정성 백본.** 노드 동작점 age-cap 이 사라진 자리를 이 하나로 통합.
- **연쇄 지연을 덮는다.** 복귀 요청의 *풀-내 대기* 를 상한 → 멀티턴 연쇄 지연이 bound.
  (think-gap 자체는 유저 시간이라 비제어.)

## 세 가지 age 정리

| age | 위치 | 역할 | 본 설계 |
|---|---|---|---|
| 노드 동작점 age-cap | 노드 풀 | 노드 내 steering 공정성 | **사라짐** (결정론 → starvation 구조적 0) |
| cache evict-age | 노드 캐시 | idle KV 방출 | 신설 (스윕) |
| **글로벌 풀 age-cap** | 라우팅 층 | 글로벌 풀 starvation 방지 | 신설 — **주 공정성 백본** (스윕) |

## 글로벌 풀 = 대용량 유한 큐

- best-of-K(무기억 복원추출)는 도착 시각·정체성·큐가 없어 FIFO/글로벌 age-cap 을 표현 못 한다.
  → **도착 타임스탬프 달린 유한 큐** 필수.
- **개수는 아주 많게.** 특정 길이가 고갈되지 않아야 각 노드 평균을 정밀 제어 가능하고, 실서버의
  글로벌 풀에도 근접한다.
- **재요청(복귀) 확률 = 길이 의존**: mid·long 높게, short 낮게(코딩/실무가 길고 멀티턴 잦음 —
  캐시 정책과 일관). 평균 ~2.5턴(LMSYS ~2 / WildChat ~2.52) → 턴당 continue≈0.6 / end≈0.4.
  *체리피킹이 아니라 본 프로젝트의 주장이므로 정당.*

## 스윕 knob (3)

1. **캐시 적격 길이 임계** — 이 길이 넘는 것만 캐싱.
2. **evict-age** — 캐시 idle 방출 임계.
3. **글로벌 풀 age-cap** — 강제 라우팅 임계 (+ 강제 진입 개수 카운트).

(캐시 capacity 는 스윕 아님 — derive 잔여 고정.)

## 측정 / 검증 / 비교

- **비교군 셋업:** 동일한 대용량 유한 큐 위에서 **(A) 현 로컬 steering(잉여+힐링) port** ↔
  **(B) 신규 글로벌 결정론 pre-positioning** 대조. (무한풀 baseline 99.53%/Σ1.666% 과 직접 비교는
  best-of-K richness 가 교란이라 부적절 — 큐로 통일.)
- **지표:** Σdev(평균·최악·miss 분류) · p99 tail · edge 비율 · **글로벌 강제율** ·
  **캐시 히트율(evict-age·적격임계 함수, knee)** · **누적 절약(시간/트래픽, reload=속도×길이)** ·
  100K 유지 여부.
- **검증 질문:**
  - 멀티턴 복귀 도착 jitter 흡수에 필요한 *최소 슬랙*? (디코드는 결정론 → 슬랙 0; 복귀만 stochastic.)
  - 글로벌 제어 latency 가 forward-pass 박자를 따라가나? (churn 낮음 → set-change 때만 재계산.)
    못 따라가면 thin 로컬 fallback 이 필요한가?
  - 캐시가 tail(p99 TTFT, 복귀 턴)을 얼마나 줄이나?

- **이득의 본질 = 평균 idle 절감(이미 ~0, PIM 이 GPU-A 밑에 숨음) 이 아니라**
  → **tail latency(p99 TBT/TTFT) 보장 + 요청 KV 이동 은닉 + 적대분포 견고함 + 멀티턴 재계산 절약.**
