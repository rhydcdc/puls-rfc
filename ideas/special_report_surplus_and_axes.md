# 스페셜 리포트 — 잉여의 역할 & 두 축(max_tokens vs per-layer KV)의 구분

> 토론으로 드러난 두 핵심: ① **잉여가 매-라운드 재선택(steering)을 가능케 하는 결정적 자원**이다. ② 그동안
> 섞여 있던 **`max_tokens`(시간 축)** 와 **`6.21M`(레이어당 KV 축)** 은 전혀 다른 것이다.

---

## 1. 디코드 루프 메커닉 (코드 확정)
- 디코더는 노드 디코드 풀에 **상주**하며 **한 라운드 = 한 forward-pass = 토큰 1개** 생성. `dec` 0→max_tokens 로 매 라운드 +1.
- 읽는 KV = `live_kv = prompt + dec` → **매 라운드 +1 커진다**(생성한 토큰이 다음 스텝 컨텍스트에 추가).
- `dec ≥ max_tokens` 일 때만 **완료·퇴출**(B 는 이때 캐싱). 그 전까진 계속 상주 → **토큰 사이 KV 리로드 0**(vLLM 도 동일). 리로드는 *턴 사이*(멀티턴)에만.

## 2. 두 축의 구분 (그동안의 오해 해소)
| | `max_tokens` | `6.21M` (kv_operating_target) |
|---|---|---|
| 무엇 | **각 요청의 decode 길이 = 루프 라운드 수** | **62-배치가 *한 스텝·한 레이어*에 읽는 Σ live_kv** |
| 축 | **시간**(얼마나 오래 도느냐) | **공간**(한 번에 얼마나 읽느냐) |
| 의미 | **랜덤 EOS 분포의 결정론 모델링 상수**(현실 EOS 는 랜덤, 모델은 max_tokens 로 치환) | PIM per-layer 읽기 타깃 |

- **`6.21M` 은 *레이어당*** 이다. `t_pim(6.21M)` = 한 레이어 decode-attn 시간 → forward-pass 는 80 레이어 반복 → **TBT = (레이어당 max(t_pim,t_gpu_a,t_ffn)) × 80**. 한 스텝 안의 80 레이어가 모두 동일한 6.21M 을 읽는다.
- 둘은 **다른 축**이다: max_tokens 는 "몇 라운드 도느냐", 6.21M 은 "한 스텝에 얼마 읽느냐". (이 둘을 같다고 본 게 오해였다.)

## 3. A vs B — 잉여가 결정적이었다
- **A (잉여 10, 풀 134)**: 매 라운드 **134 중 124 재선택**(steer). live_kv 높은 ~10 을 *일시정지*(상주 유지, 다음 라운드 재선택, age-cap 이 정지 bound, 결국 max_tokens 찍고 퇴출). → **풀이 떠 있어도(105K) 배치는 낮은 62 를 골라 6.21M 유지** → **Σdev 1.5%**.
- **B (잉여 0, 풀 124)**: 124 전원 매 라운드 일괄 dec++, **재선택 불가**(고를 여분 0). 배치 = 풀 전체 → 풀 drift 를 그대로 상속 → **Σdev 7.6%**.

> **핵심: Σdev 격차는 *refill source*(글로벌 vs 잉여)가 아니라 *매-라운드 재선택* 차이다.**
> 재선택은 *상주 디코더 여분*이 있어야 가능하고(=잉여), 큐(미상주·prefill 안 됨)는 그 후보가 못 된다.
> **잉여 = 단순 여유분이 아니라, 떠오른 풀에서 target-미달 부분집합을 뽑게 해주는 버퍼였다.**

## 4. 왜 B 풀평균이 108K 로 뜨나 (drift 분해)
- **dec 누적: ~1%.** 평균 dec ≈ max_tokens/2 ≈ 1088 ≈ 100K 의 1.1% (네가 직관한 "6.21M 위로 조금씩 쌓임" — 방향 맞음, 크기 작음).
- **프롬프트 inflation: ~7% (주범).** 멀티턴 복귀가 누적길이라 더 길고(resid 가 B 는 mid/long 으로 쏠림: 15/76/9 vs A 18/73/9), **B 는 이를 매-라운드 재선택으로 깎아낼 수단이 없다**(ideal 이 음수가 돼도 음수 길이를 못 당김).
- A 는 같은 inflated 풀에서도 **낮은 62 를 골라** 6.21M 유지 → drift 무관.

## 5. 함의
- **A 의 매-라운드 steering 은 "랜덤 EOS(max_tokens)로 길이가 제각각인 요청이 흘러드는 와중에, 매 스텝 per-layer 6.21M 을 맞추고 굶김 0" 을 동시에 해내는 로직** — 잉여가 그 자유도를 준다.
- B 가 잉여를 없애 캐시 공간을 벌면, **그 대가로 매-라운드 재선택 자유도(=낮은 Σdev)를 잃는다.** → HBM 을 *잉여(낮은 Σdev/TBT)* vs *캐시(낮은 TTFT)* 로 나누는 트레이드오프.
- 다음 실험 후보: B 에 **상주 reservoir 크기**를 파라미터로 두고(글로벌이 그 reservoir 에서 매 라운드 steer) 0→큰 값 스윕 → Σdev↓ 와 캐시 용량↓ 의 knee 정량화.

---
*경계: 절대값(6.21M·100K·TBT)은 Llama70B+B200 derive 값. max_tokens 분포·offload_bw·β 는 가정 라벨.*
